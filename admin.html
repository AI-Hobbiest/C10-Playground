Admin access and account security

The Admin Workspace contains no GitHub write token or server-side authentication. Publishing account files and content is controlled by GitHub repository permissions.

Student passwords: only salted hashes are committed in data/student-accounts.json. Because the file is public and verification happens in the browser, this is not a secure login system. Use unique classroom-only passwords, never reuse passwords, and migrate to a server-side verifier before using accounts for protected data.

Operations and release checklist

Before publishing

Export changed bank JSON, download each new image/resource file, upload every file to the exact referenced path, and check that all image references resolve.

Validate

Wait for GitHub Actions to pass. Invalid JSON, malformed MCQs or missing assets should be fixed before publication.

Keep repository size under control

Prefer compressed, appropriately sized diagrams. Avoid duplicate textbook PDFs, large videos and base64 images embedded in thousands of questions.

Back up private data

Keep individual student backups in a private location. Never commit student backup files, passwords, access tokens or private reports to this public repository.

Later improvements: server-side authentication, private account storage, admin-only account management, cross-device progress sync, centrally collected attempts and live reports. Cloudflare Worker + D1 remains an option, but is not needed for the current starter phase.
